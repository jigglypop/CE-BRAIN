# 검증 상태와 재현 범위

## 1. 세 가지 완료를 구분한다

문서 게시, 계산 재현, 생물학적 설명의 독립 검증은 다르다. 이 묶음은 연구 원고의 통합과 게시를 목적으로 한다. 과거 보고서의 실행·검사 횟수를 이번에 전부 재실행한 것처럼 쓰지 않는다. 원문 안의 ‘이번 실행’과 ‘원격 변경 없음’은 각각 원보고서 작성 시점의 기록이다.

전체 통합 기전에 새 증거 등급을 부여하지 않는다. 합성 구현, 처리된 생물 관측의 후향 비교, 독립 개입 검증의 부재를 분리한다. 사용자 기본 리만 전제는 유지하지만 기전의 미완성을 관측 오차 감소로 대신하지 않는다.

## 2. Git에 포함한 자료와 원 ZIP에 남긴 자료

Git에는 원문 보고서 17편, 그 SHA-256, 최신 저장 계량·설정, 주 평가의 42개 개별 예측, 네 평가의 요약, 추가 32분할 요약, 과거 검산 JSON과 게시용 검사 스크립트를 포함한다. 주 평가 이외의 개별 예측 전체·원자료 CSV·실험별 코드·대형 배열은 기존 14개 전달 ZIP에 남겨 두며, 이 Git 추가분에 전량 복제했다고 하지 않는다. 원자료의 저자 저장소·고정 커밋·해시는 출처 manifest에 명시했다.

`historical_validation.json`은 최신 원보고서의 과거 실행 기록이다. 게시 검사 결과는 별도로 남긴다. 원문 보존 과정에서는 전사 오타를 원본과 대조해 복원하며 연구 내용을 수정하지 않는다.

## 3. 검사 명령

저장소 루트에서 다음 명령을 실행한다. Python 3.10 이상과 NumPy가 필요하다.

```bash
python research/ce_brain_publication_20260919/verify_publication.py
```

이 명령은 보존 파일 해시, 주 평가 RMSE·MAE 재계산, 모델의 SPD, 기존 입력 예제의 선형계 출력, 추가 논문 20개와 입구·원장의 상대 링크를 검사한다. 증거 폴더만 별도로 확인할 때는 `--evidence-only`를 사용한다.

이 검사는 모델의 재적합, 236개 설정 재탐색, 독립 생물 실험이 아니다. 원본 실험을 재실행할 때는 각각의 전달 ZIP에서 해당 실행환경·명령·데이터 요구조건을 따라야 한다. 이 Git 추가분만으로 전체 MaleCNS나 모든 과거 실험을 실행할 수 있다고 주장하지 않는다.

## 4. 실패와 미확인 보존

첫 리만 후보의 비개선, 큰 SPD 보정의 기록 분리 악화, 공분산 자동선택 악화, 22°C의 다른 순위, 일부 영역 잔차 증가를 원문과 결과 장에 남긴다. 회귀의 기울기 등식을 보편 생물학 법칙으로 사용하거나 별도 회귀 RMSE를 합성 회로의 성능으로 사용하는 해석은 채택하지 않는다.

## 5. 게시 검사의 범위

연결 GitHub API로 원격 트리와 문서를 읽고, 추가 파일만 새 트리로 구성한다. 직접 Git 복제는 컨테이너 DNS 제한으로 불가능했다. 따라서 기존 저장소 전체의 Windows 배포 하네스를 실행했다고 쓰지 않는다. 게시 시점에 실제 실행한 증거 검사와 원격 파일·브랜치 확인은 별도 영수증에 기록한다. 강제 갱신이나 기존 이력 재작성은 사용하지 않는다.
